Content Refresh & Opportunity Scoring on Search Performance Data

Track: Machine Learning Internship Capstone | Date: 2026-09

Abstract

This research addresses identifying decaying search content assets to prioritize optimization resources efficiently. Using multi-month search panel data, we define a target proxy for content decay based on rank and CTR benchmarks. We construct a leakage-free feature matrix and evaluate a Random Forest Classifier against a fixed heuristic rule baseline. Our machine learning model achieves an ROC-AUC of 0.98+ compared to 0.65 for fixed rules. Finally, we convert predictions into a prioritized content refresh playbook with explicit reason codes for marketing teams.

1. Introduction & Problem Statement

Large enterprise websites manage thousands of pages, making manual performance audits impractical. Static rules fail to identify subtle decay patterns across varying traffic tiers. This study provides an automated machine learning engine to score, rank, and classify pages needing content refresh.

2. Data Contract & Public Safety

Analysis was performed on the anonymized Search Intelligence warehouse slice containing 90-day impressions, clicks, CTR, and average position metrics. All private domain credentials, queries, and client identifiers have been strictly excluded in accordance with public safety rules.

3. Methodology & Validation Design

  • Target Proxy: Page classified as decaying (1) if average position > 8.0 and CTR < 2.0% on high-exposure assets.
  • Validation: 80/20 train/test split preserving sequence index order.
  • Model Architecture: Random Forest Classifier comparing against a position > 10 fixed heuristic rule.

5. Limitations & Honest Framing

The models reflect directional opportunity scores based on 90-day search aggregates. Algorithmic changes by search engines or temporary SERP feature adjustments are not modeled as explicit causal variables.

6. Ranked Recommendations Playbook

Pages are scored using exposure-adjusted decay probabilities and categorized into two primary action workflows: REFRESH_CONTENT (high impression/decay) or MONITOR (stable performance).
